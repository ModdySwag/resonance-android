# Pre-release audit — 2026-11-07

Four independent audit streams (build/release, security, device runtime, code quality) run
against HEAD before this pass, plus a manual review of the update path. Numbers below are
measured, not estimated. Fixes applied in this pass are marked **fixed**; the rest is the
remaining queue in severity order.

## Blockers for Play (sideload unaffected)

1. **targetSdk 35** — Play requires API 36 since 2026-08-31. **fixed**: compileSdk/targetSdk 36,
   build verified, APK installs and runs on API 30 and API 36.
2. **Self-updater + REQUEST_INSTALL_PACKAGES** violates Play's Device & Network Abuse policy.
   Not fixed by design — the app is sideload-first. Fix when submitting: a `play` flavour whose
   manifest removes the permission (`tools:node="remove"`), a stubbed updater, and Play In-App
   Updates (`com.google.android.play:app-update`).

## High

3. **Release lint gate red and never run in CI.** **fixed**: `lint { abortOnError true;
   checkReleaseBuilds true }`; `assembleRelease` now runs lintVital and is green. The four
   errors themselves (NewApi x3, UnspecifiedRegisterReceiverFlag) collapse to one real fix —
   the receiver call now uses the 3-arg API-26 overload; the NewApi items need
   `@TargetApi(33)` extraction and `values-v27` themes (**open**, cosmetic).
4. **R8/shrinking off.** **fixed**: minify + shrinkResources + keep rules for
   `@JavascriptInterface`. Measured: APK 865,554 → **861,762 B**, dex 25,889 → **20,358 B**,
   class names gone; bridge verified on device (Bridge.log "shim ready" after shrinking).
   Resource shrinking reclaims 0 B (nothing unused).
5. **allowBackup=true with no rules** — WebView localStorage (imported packs, favourites)
   went to Google Drive/device transfer and adb backup. **fixed**: allowBackup=false plus
   `data_extraction_rules.xml` excluding everything.
6. **CI "is it signed" check greps META-INF**, which a v2-only APK does not use — it passes
   unsigned builds. **open**: replace with `apksigner verify --strict`.
7. **Updater trusts page-supplied URL + hash** (`Bridge.updateApp`) and **fails open when
   sha256 is absent**. **fixed**: https + moddys.net allowlist, 64-hex checksum required at
   download *and* install, receiver NOT_EXPORTED.
8. **No automated tests for the Java layer** (1,354 non-blank lines, 0%). **open** — see the
   ten-test plan at the end; this is the largest remaining quality gap.

## Medium

9. **Unconditional 15 fps redraw loop** (`assets/www/app/app.js` raf) — a paused app renders
   293-302 frames per 20 s and burns 1.6-2.2 CPU cores; during playback it starves the audio
   callback (audible underruns). **open**: demand-driven redraw (250 ms while playing, stop when
   idle/hidden, cap dpr at 2, blit a static curve and move only the playhead).
10. **WebView hardening relied on targetSdk defaults.** **fixed**: file/content access off,
    mixed content never, safe browsing on.
11. **No CSP on the bundled page.** **open**: return `default-src 'self'; frame-src 'none';
    object-src 'none'; base-uri 'none'; form-action 'none'` from `shouldInterceptRequest`.
12. **Renderer crash loses the session** (audio stops, UI returns to IDLE at 0:00, no resume).
    **open**: persist {sessionId, position, playing} every 5 s and restore on boot.
13. **Two active media tracks** after a route change/rotation (monkey run) — a second output
    stream; double binaural generation corrupts the beat. **open**: single-context guard,
    idempotent play(), suspend the context on pause.
14. **Save session leaks on activity destroy**, leaving a truncated file in Downloads.
    **open**: `if (save != null) save.abort()` in onDestroy.
15. **One BroadcastReceiver per update tap**, never unregistered on failure. **open**.
16. **Throttled update check skips its callback**, so a launch check can leave the UI in
    "unknown". **open**: answer with both-null on the throttled path.
17. **Foreground-service start failure swallowed** on Android 12+ — playback silently has no
    notification. **open**: report to the page and retry on resume.
18. **Version drift**: RELEASE_NOTES/listing/data-safety still say 2.0.0-beta; CI never
    asserts tag == versionName. **open**.
19. **No Gradle wrapper** (build depends on a local Gradle 8.7) and no dependency
    verification. **open**: commit the wrapper with a distribution SHA-256.
20. **Signing is v2-only** (no v3 rotation, no v4 incremental). **open**: `enableV3Signing`
    / `enableV4Signing` in the release signing config.
21. **Imported zip/gnaural files have no size cap** — a zip bomb materialises in the renderer.
    **open**: reject >32 MB and cap decompressed entry size/count.

## Low (open)

22. `esc()` missing on device strings in the Check panel (innerHTML sink).
23. `Bridge.log` writes page text and file paths to logcat at INFO; gate on debuggable.
24. 37 empty `catch (e) {}` in the shim; five sit on state-changing paths and hide failures.
25. 19 javac deprecation warnings (pre-API-30 system bar API) — migrate to WindowInsetsController.
26. Duplicated colour/label literals in Java and CSS tokens can drift.
27. `Compat` caches a failed asset read for the process.
28. No baseline profile (small gain: dex is 20 KB).

## The ten tests that would catch the most

1. Feed ahead of build → `available`, code, fields round-trip.
2. Malformed/offline feed → one error callback, no throw.
3. Throttled launch check still answers.
4. `versionCode()` failure must not fabricate an update.
5. Checksum mismatch/truncated download aborts before any installer intent.
6. Update URL off-host or non-https is refused.
7. Foreground service enters as mediaPlayback with the right notification.
8. Pause/stop/task-removal lifecycle keeps or clears the notification correctly.
9. Save session: single writer, error contract, and abort-on-destroy deletes the row.
10. Bridge state under denied POST_NOTIFICATIONS and after activity teardown.
